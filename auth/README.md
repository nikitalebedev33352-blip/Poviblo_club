# Повидло Клуб — Authorization Service

Отдельное приложение на Flask, которое проверяет логин и пароль пользователей в существующей базе PostgreSQL и выпускает **Access Token (JWT)** с подписью **RS256**. Это сервер авторизации проекта, а не основной API для встреч и других ресурсов.

## Структура

```text
auth/
├── main.py                 # точка входа, запуск Flask
├── auth_service/
│   ├── __init__.py
│   ├── app.py              # HTTP-ручки
│   ├── config.py           # настройки из переменных окружения
│   ├── db.py               # чтение пользователей из PostgreSQL
│   └── tokens.py           # выпуск и проверка JWT
├── requirements.txt        # зависимости Python
└── README.md
```

## HTTP API

| Метод и путь | Назначение |
| --- | --- |
| `GET /health/live` | Проверка, что процесс приложения работает; ответ 200 |
| `GET /health/ready` | Проверка доступности PostgreSQL; ответ 200 или 503 |
| `POST /auth/login` | Принимает JSON с `login` и `password`, проверяет пароль и возвращает JWT |
| `GET /auth/me` | По заголовку `Authorization: Bearer <JWT>` возвращает профиль пользователя |

Пример тела запроса на вход:

```json
{"login": "testuser", "password": "ваш-пароль"}
```

Успешный ответ содержит `access_token`, `token_type` (`Bearer`) и `expires_in` (по умолчанию 900 секунд). При неверных учётных данных возвращается 401.

## Подключение и настройки

Обязательные переменные окружения:

- `DB_HOST` — адрес PostgreSQL внутри Docker-сети (например, имя сервиса БД).
- `DB_NAME` — имя базы данных.
- `DB_USER` — пользователь PostgreSQL.
- `DB_PASSWORD` — пароль PostgreSQL.
- `JWT_PRIVATE_KEY_PATH` — путь к файлу приватного RSA-ключа **внутри контейнера**.

Необязательные переменные:

| Переменная | Значение по умолчанию |
| --- | --- |
| `DB_PORT` | `5432` |
| `JWT_ISSUER` | `povidlo-auth` |
| `JWT_AUDIENCE` | `povidlo-api` |
| `JWT_KEY_ID` | `povidlo-auth-key-1` |
| `JWT_ACCESS_TOKEN_MINUTES` | `15` (допустимо 1–60) |

Приложение слушает порт **8081**. В целевой архитектуре внешний Nginx направляет запросы `/auth/*` в этот сервис. PostgreSQL доступен ему по внутренней сети Docker.

## RSA, сертификаты и JKS

Сейчас приложение читает **приватный RSA-ключ в формате PEM без шифрования** (не менее 2048 бит) из файла, указанного в `JWT_PRIVATE_KEY_PATH`. Файл предоставляется при запуске, например через секрет или volume с доступом только на чтение. Приватный ключ и пароли **не должны попадать в Git или Docker-образ**.

В дальнейшем мы реализуем учебный процесс выпуска сертификата X.509, упаковки ключа и сертификата в P12, импорта в JKS и выбора записи по alias. Для Python-приложения потребуется безопасно предоставить ключ из хранилища в подходящем формате. Само по себе переименование `.p12` в `.jks` не является импортом.

Основной **Resource API** должен получать **только публичный ключ или сертификат** и самостоятельно проверять подпись RS256, `iss`, `aud`, срок действия токена и права пользователя. Приватный ключ Resource API не нужен.

## База данных

Используется уже существующая таблица:

`users(id, login, password_hash, full_name, nickname, photo, birth_date, created_at)`.

Этот сервис **не создаёт и не изменяет структуру таблиц**. Пароли сверяются через `werkzeug.security.check_password_hash`; значение `password_hash` должно быть создано совместимым алгоритмом, например через `generate_password_hash`. Заглушка `temporary_hash` не подходит для входа.

## Ограничения текущей версии

Это учебный MVP, **не готовый публичный Identity Provider**. Пока нет регистрации, восстановления пароля, refresh-токенов, отзыва токенов, ограничения частоты попыток входа и аудита. До публикации в интернете необходимо добавить защиту от перебора, HTTPS на Nginx, безопасную работу с токенами в браузере, управление секретами и запуск через production WSGI-сервер вместо встроенного сервера Flask.

## Дальнейшие этапы

1. Развернуть Authorization Service в отдельном контейнере и подключить PostgreSQL.
2. Подготовить настоящий хеш пароля для тестового пользователя и проверить вход.
3. Создать Resource API, который проверяет подпись JWT публичным ключом.
4. Настроить Nginx: frontend `/`, Authorization Service `/auth/*`, Resource API `/api/*`.
5. Отработать выпуск сертификата, P12, JKS, алиасы и ротацию RSA-ключей.
